# 在线临时群聊设计

日期：2026-06-28

## 目标

在现有多用户聊天系统中实现真正由 C 服务端维护的在线临时群聊，替换当前 Web 前端硬编码的默认群组。群聊应具备在线聊天室效果：创建者只能从当前在线用户中选择成员，创建者自动加入；成员离线或 TCP 断开时自动退出相关群聊；群成员为空时服务端自动删除群。

## 非目标

- 不实现持久群聊；服务端重启后群数据消失。
- 不允许加入离线用户。
- 不实现邀请确认流程；创建者勾选成员后直接加入。
- 不实现群主权限、踢人、群改名、手动解散、管理员等能力。
- 不实现好友关系系统；成员来源只使用当前在线用户列表。

## 当前系统事实

当前 Web 前端在 `web/public/main.js` 中硬编码了多个默认群组，这些群并不来自服务端。Web 网关的 `send_group` 会转成 C 协议中的 `MSG_GROUP`。C 服务端当前 `handle_group()` 的语义是把消息广播给所有其他在线用户，没有群 ID、群成员列表或群生命周期管理。

为了避免继续扩展假群组，本次设计会把 Web UI 的群聊入口改成服务端群能力。旧的全局广播语义可以保留用于兼容已有 C 客户端或测试，但 Web UI 不再依赖它。

## 协议设计

新增或升级以下群聊相关消息类型：

- `MSG_GROUP_CREATE`：创建在线临时群。
- `MSG_GROUP_LIST`：请求当前用户所在群列表。
- `MSG_GROUP_MESSAGE`：向指定群发送消息。
- `MSG_GROUP_EVENT`：服务端主动推送群创建、成员变化、群删除等事件。

`MSG_GROUP` 可保留为旧的全局广播兼容路径；Web UI 使用新的指定群协议。

群创建请求包含群名和成员用户名列表。服务端收到后校验：

- 请求者必须已登录。
- 群名不能为空，长度在协议限制范围内。
- 被选择成员必须是当前在线用户。
- 创建者自动加入，即使请求 payload 中未包含创建者。
- 成员去重，非法或离线成员会导致创建失败并返回错误。

群消息请求包含 `group_id` 和文本内容。服务端校验发送者仍是该群成员后，转发给群内所有当前在线成员。为了让前端正确归档消息，服务端转发的群消息需要带 `group_id`、`group_name`、`sender` 和文本内容。

## 服务端模型

C 服务端新增内存态 `GroupStore`。每个群包含：

- `group_id`：服务端生成的短 ID。
- `name`：群名。
- `creator`：创建者，仅用于展示或调试，不决定生命周期。
- `members[]`：当前在线成员用户名列表。

群只存在于服务端内存，不写入文件。服务端重启后所有群清空。

成员离线处理必须接入现有登出路径，包括显式 logout、TCP 断开、发送失败导致的被动下线。用户离线时，服务端从所有群移除该用户：

- 如果群还有剩余成员，向剩余成员推送成员变化事件。
- 如果群成员数变为 0，删除该群。
- 创建者离线不解散群，只要还有其他成员在线，群继续存在。

## Web 网关设计

Web 网关新增浏览器动作：

- `create_group { name, members }`
- `group_list`
- `send_group_message { groupId, text }`

Web 网关将这些动作编码为新的 C 协议包，并将 C 服务端返回或推送转换为浏览器事件：

- `group_list { groups }`
- `group_event { event, group }`
- `chat_message { mode: 'group', groupId, groupName, sender, text }`

网关仍负责登录态校验、字段长度校验、JSON 错误提示和 TCP 断开后的会话清理。群创建、群列表和群消息都必须要求用户已登录。

## 前端 UI 设计

删除当前硬编码的默认群组。登录后群列表初始为空，前端自动请求在线用户列表和群列表。

群组 tab 增加“新建群聊”入口。创建群对话框包含：

- 群名输入框。
- 当前在线用户列表，排除当前登录用户。
- 多选控件用于选择要加入群的在线用户。
- 创建按钮。

创建者自动加入群，不需要在成员列表中勾选自己。如果没有其他在线用户，对话框显示空状态并禁用创建。

群创建成功后，所有成员通过服务端推送更新群列表。群消息按 `groupId` 存入对应会话；收到群消息时不自动切换当前会话。如果用户当前正在查看该群，会话消息即时渲染；否则保留在对应群记录中等待用户点击。

成员离线或群删除时，前端根据 `group_event` 更新群列表和当前会话状态。如果当前会话对应的群已删除，消息区显示系统提示并要求用户选择其他会话。

## 数据流

创建群：

1. 用户打开群组 tab，点击新建群聊。
2. 前端展示当前在线用户，用户输入群名并勾选成员。
3. 前端发送 `create_group` 到 Web 网关。
4. 网关编码为 `MSG_GROUP_CREATE` 发给 C 服务端。
5. 服务端校验成员在线状态并创建群。
6. 服务端向所有群成员推送 `MSG_GROUP_EVENT`。
7. 网关转发为 `group_event`，前端更新群列表。

发送群消息：

1. 用户选中群会话并发送文本。
2. 前端发送 `send_group_message { groupId, text }`。
3. 网关编码为 `MSG_GROUP_MESSAGE`。
4. 服务端校验发送者属于该群。
5. 服务端向群内在线成员转发群消息。
6. 网关转发为 `chat_message`，前端按 `groupId` 归档。

成员离线：

1. 服务端在 logout 或 TCP 断开路径识别用户离线。
2. 服务端从所有群移除该成员。
3. 服务端删除空群或向剩余成员推送成员变化事件。
4. 前端根据事件更新群列表和会话状态。

## 错误处理

- 创建群时没有选择在线成员：前端禁止提交，服务端仍做校验兜底。
- 成员在提交前离线：服务端返回错误，前端提示重新选择在线成员。
- 群名非法或过长：前端和服务端都校验。
- 用户不在群中却发送群消息：服务端返回错误。
- 群不存在或已删除：服务端返回错误，前端移除或标记对应群会话。
- TCP 断开：沿用现有 `logged_out` 流程清空前端登录态。

## 测试计划

C 层测试：

- 创建群时创建者自动加入。
- 只能选择当前在线用户。
- 群消息只发送给群成员，未加入用户收不到。
- 成员离线后自动退出群。
- 群成员为空时自动删除。

Web 网关集成测试：

- 多个 WebSocket 客户端登录后，A 创建群并选择 B。
- A 和 B 收到群创建事件，C 不收到。
- A 发送群消息，B 收到，C 收不到。
- B 退出后，A 收到成员变化事件。
- 群列表拉取能返回当前用户所在群。

前端验证：

- 页面不再显示原来的默认群。
- 登录后群列表为空或显示服务端返回的真实群。
- 新建群聊只能勾选在线用户。
- 创建成功后群出现在成员的群列表中。
- 群消息进入对应群会话，不自动切换当前会话。

回归验证：

- 注册、登录、私聊、文件传输、UDP 广播继续通过。
- 现有 TCP 断开和登录态处理继续通过。

## 验收标准

- Web 前端不再显示硬编码默认群。
- 用户可以创建在线临时群，并只能选择当前在线用户。
- 创建者自动加入群。
- 群消息只发给该群成员。
- 成员离线后服务端自动从群中移除该成员。
- 群空后服务端自动删除。
- 群列表通过服务端推送更新，并支持前端拉取兜底。
- 已有核心聊天能力不回归。
